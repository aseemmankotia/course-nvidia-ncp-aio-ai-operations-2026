## Chapter 4: Slurm Cluster Administration for AI Workloads — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Slurm GrpTRES vs MaxTRES vs GrpTRESMins—what's the difference? | GrpTRES = total simultaneous resources for account/QOS (e.g., max 10 GPUs running at once). MaxTRES = per-user or per-job limit. GrpTRESMins = cumulative resource-minutes over time (e.g., 1000 GPU-hours/quarter). Exam tests: GrpTRESMins for quota enforcement, GrpTRES for concurrent limits. |
| 2 | Which scontrol command drains a node for maintenance without killing running jobs? | scontrol update NodeName=node01 State=DRAIN Reason='Maintenance'. DRAIN prevents new jobs, allows current jobs to finish. After maintenance: State=RESUME. Exam tip: State=DOWN kills jobs immediately (emergency only). |
| 3 | What must be in slurm.conf BEFORE gres.conf GPU allocation works? | GresTypes=gpu (global config). Without this, Slurm ignores all gres requests. After adding, restart slurmctld. Exam trap: gres.conf can be perfect, but jobs stay PENDING if GresTypes is missing. |
| 4 | MIG configuration: Does gres.conf CREATE MIG instances or DECLARE existing ones? | DECLARE only. Admin must first create MIG slices with 'nvidia-smi mig -cgi 1g.10gb -C' (or nvidia-mig-parted). Then gres.conf tells Slurm they exist. Exam mistake: assuming gres.conf auto-creates MIG. |
| 5 | Fair-share priority: PriorityWeightFairshare=10000 vs PriorityWeightAge=1000—which dominates? | FairShare dominates (10× weight). New users get ~10000 priority points (fairshare≈1.0), heavy users get <5000 (fairshare<0.5). Age adds ~1 point/minute. Exam scenario: explain why new user's job jumps queue. |
| 6 | How to enforce 1000 GPU-hours per user per quarter with Slurm accounting? | sacctmgr modify user name=alice set GrpTRESMins=gres/gpu=60000 (1000 hrs × 60 min). Reset quarterly. Jobs held when limit reached. Exam tip: GrpTRESMins = cumulative, MaxTRESMins = per-job. |
| 7 | Partition preemption: How to make 'guaranteed' partition preempt 'spot' partition jobs? | Set PriorityTier=2 on guaranteed, PriorityTier=1 on spot. Enable PreemptType=preempt/partition_prio in slurm.conf. Higher tier preempts lower tier. Exam: know PriorityTier (partition) vs Priority (QOS). |
| 8 | sacctmgr: Create account 'ml_team' with max 8 concurrent GPUs—exact command? | sacctmgr add account ml_team Cluster=ai-cluster; sacctmgr modify account ml_team set GrpTRES=gres/gpu=8. GrpTRES = group total simultaneous limit. Exam: don't confuse with MaxTRES (per-user). |
| 9 | squeue -o %Q shows priority. What does %Q display exactly? | Job priority (numeric value). Higher = scheduled first. Calculated from: Age + FairShare + JobSize + QOS_Priority. Exam: use %Q to debug why jobs aren't starting. |
| 10 | Node states: IDLE vs ALLOCATED vs DRAIN vs DOWN—definitions? | IDLE = available, no jobs. ALLOCATED = running jobs. DRAIN = no new jobs, current jobs finish. DOWN = offline, kills jobs. Exam: DRAIN for maintenance, DOWN for hardware failure. |
| 11 | gres.conf for A100 with 7 MIG slices (1g.10gb)—correct syntax? | NodeName=node01 Name=gpu Type=a100-1g.10gb File=/dev/nvidia0 Cores=0-7 Count=7. Count = number of MIG slices. Cores = CPU affinity. Exam: Count must match physically created MIG instances. |
| 12 | QOS MaxWall=04:00:00 vs partition MaxTime=08:00:00—which limits job? | Whichever is LOWER. QOS MaxWall overrides partition MaxTime if stricter. Job fails if requested time exceeds both. Exam: timelimit hierarchy: job request < QOS MaxWall < partition MaxTime. |
