## Chapter 5: Kubernetes and Run:ai for AI Infrastructure — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | What are the three core GPU Operator components for device management, monitoring, and container runtime? | nvidia-device-plugin (advertises GPUs to Kubernetes scheduler), nvidia-dcgm-exporter (exposes GPU metrics for Prometheus), nvidia-container-toolkit (enables GPU access in containers). Exam tip: dcgm-exporter = monitoring, device-plugin = scheduling, container-toolkit = runtime. |
| 2 | Command to create Kubernetes ResourceQuota limiting namespace 'ai-team' to 8 GPUs? | kubectl create quota gpu-limit --hard=nvidia.com/gpu=8 -n ai-team. Exam tip: ResourceQuota is separate object from namespace. Use --hard flag with resource name nvidia.com/gpu. |
| 3 | Run:ai project quota vs over-quota limit? | Quota = guaranteed resources (always available). Over-quota = maximum burstable resources when cluster has idle capacity. Example: quota=4, over-quota=8 means guaranteed 4 GPUs, can use up to 8 if available. Exam tip: over-quota enables bursting, not guaranteed. |
| 4 | What is Run:ai fractional GPU allocation minimum granularity? | 0.01 GPU (1%). Can allocate 0.25, 0.5, 0.75 GPU, etc. Exam tip: Fractional GPU = memory partitioning + time-slicing, NOT hardware MIG. Used for bin-packing multiple small jobs on one GPU. |
| 5 | nvidia-device-plugin MIG strategy 'single' vs 'none'? | 'single' exposes each MIG instance as separate resource (nvidia.com/mig-3g.20gb). 'none' (default) exposes full GPUs only (nvidia.com/gpu). Exam tip: MIG requires strategy='single' + node labels with MIG config. |
| 6 | Command to label Kubernetes node with MIG profile 'all-3g.20gb'? | kubectl label node <node-name> nvidia.com/mig.config=all-3g.20gb. Exam tip: Device plugin reads this label to discover and advertise MIG instances. Label format: nvidia.com/mig.config=<profile-name>. |
| 7 | What Run:ai scheduling policy prevents deadlock in distributed training requiring all GPUs simultaneously? | Gang scheduling with min_replicas set to number of required GPUs. Ensures atomic allocation (all or nothing). Exam tip: Gang scheduling = distributed training, Bin-packing = maximize utilization, Fairness = equal distribution over time. |
| 8 | A100 80GB supports which MIG profiles? | 1g.10gb (7 instances), 2g.20gb (3 instances), 3g.40gb (2 instances), 4g.40gb (1 instance), 7g.80gb (1 instance). Exam tip: Total instances depends on profile. Mixed profiles NOT supported simultaneously on same GPU. |
| 9 | Command to submit Run:ai job requesting 0.5 GPU with image 'pytorch:latest'? | runai submit train-job --image pytorch:latest --gpu 0.5. Exam tip: --gpu accepts fractional values. Use --gpu-memory to also limit memory allocation (e.g. --gpu-memory 8G). |
| 10 | Which GPU Operator component exposes metrics: DCGM_FI_DEV_GPU_UTIL, DCGM_FI_DEV_GPU_TEMP? | nvidia-dcgm-exporter. Metrics format: DCGM_FI_DEV_* for per-device metrics. Exam tip: dcgm-exporter runs as DaemonSet, scrape endpoint :9400/metrics, integrates with Prometheus. |
| 11 | Run:ai bin-packing scheduler objective? | Maximize GPU utilization by packing multiple jobs on same GPU/node rather than spreading. Minimizes number of active nodes. Exam tip: Bin-packing = cost optimization (fewer nodes), Fairness = resource distribution equality. |
| 12 | After enabling MIG on A100 with 3g.20gb profile, what resource name does pod request for one MIG instance? | nvidia.com/mig-3g.20gb: 1 (assuming device-plugin strategy=single). Exam tip: Resource name format nvidia.com/mig-<profile>. Do NOT request nvidia.com/gpu when MIG enabled with strategy=single. |
