## Chapter 8: Troubleshooting NVIDIA AI Infrastructure — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | What is the first command to run when diagnosing 'nvidia-container-cli: initialization error'? | nvidia-ctk --version (verify toolkit installed) then sudo systemctl restart docker. Exam tip: Most nvidia-container-cli errors are fixed by verifying toolkit installation and restarting Docker daemon to reload /etc/docker/daemon.json. |
| 2 | Which service MUST be running on DGX A100/H100 systems for NVLink to work? | nvidia-fabricmanager service. Check with: systemctl status nvidia-fabricmanager. Exam tip: Inactive NVLink (nvidia-smi nvlink --status shows Link X: inactive) = fabric manager not running. This is required for NVSwitch-based topologies. |
| 3 | What configuration file does GPUDirect Storage read to identify GDS-enabled storage paths? | /etc/cufile.json with 'mountpoint' entries. Exam tip: Even if nvidia-fs driver is loaded (lsmod \| grep nvidia_fs), GDS apps need cufile.json to know which paths support direct GPU access. Missing mountpoints = GDS falls back to bounce buffers. |
| 4 | How do you enable maximum NCCL debug output for troubleshooting communication hangs? | Set environment variable: NCCL_DEBUG=INFO before running workload. Exam tip: NCCL_DEBUG=INFO shows bootstrap, transport selection (IB vs IP), ring formation. Look for 'waiting for connections' or 'Selected NCCL_IB_DISABLE=1' fallback messages. |
| 5 | Which kernel module MUST be loaded for GPUDirect RDMA between GPUs and InfiniBand NICs? | nv_peer_mem module. Verify with: lsmod \| grep nv_peer_mem. Exam tip: GPUDirect RDMA = nv_peer_mem + NCCL_IB_DISABLE=0. Without nv_peer_mem, NCCL can't do peer memory access between GPU and NIC, falls back to host memory staging. |
| 6 | What does NCCL_IB_DISABLE=0 mean, and is it required to set explicitly? | NCCL_IB_DISABLE=0 means InfiniBand transport is ENABLED (default). Usually don't need to set explicitly; set NCCL_IB_DISABLE=1 only to force TCP/IP for debugging. Exam tip: If NCCL falls back to IP, check NCCL_DEBUG=INFO for why IB wasn't selected (missing nv_peer_mem, bad cable, subnet manager down). |
| 7 | What are the required entries in /etc/docker/daemon.json for NVIDIA Container Toolkit? | { "runtimes": { "nvidia": { "path": "nvidia-container-runtime" } } }. Optionally set "default-runtime": "nvidia". Exam tip: Without this, 'docker run --gpus all' fails with 'could not select device driver nvidia'. Must restart Docker daemon after editing. |
| 8 | How do you verify InfiniBand port is active and has a LID assigned? | Run: ibstatus. Look for 'State: Active' and 'Physical state: LinkUp' plus 'base lid' value. Exam tip: If 'State: Down' or no LID, check cable/switch. If Active but NCCL fails, problem is higher in stack (nv_peer_mem, NCCL config, firewall). |
| 9 | What command tests NCCL all_reduce performance and helps diagnose multi-GPU/multi-node hangs? | nccl-tests/build/all_reduce_perf -b 8 -e 128M -f 2 -g <num_gpus>. Exam tip: Run with NCCL_DEBUG=INFO. This is the standard test for NCCL troubleshooting. Hangs reveal ring formation issues, bandwidth tests reveal degraded connectivity. |
| 10 | Fabric manager vs NVLink: when is fabric manager required? | Fabric manager is REQUIRED on NVSwitch systems (DGX A100, DGX H100, HGX). NOT needed on PCIe-based NVLink (e.g., consumer RTX cards). Exam tip: DGX/HGX = NVSwitch = need nvidia-fabricmanager service. Check: nvidia-smi nvlink --status + systemctl status nvidia-fabricmanager. |
| 11 | How do you verify GPUDirect Storage driver (nvidia-fs) is loaded and test GDS performance? | Check driver: lsmod \| grep nvidia_fs. Test: gdsio -f <device> -s 1G -w 4 -d 0 (writes 1GB to device using GPU 0). Exam tip: gdsio shows if GDS is working. Low bandwidth = check cufile.json mountpoint config or filesystem type (XFS/ext4 supported, not NFS). |
| 12 | What does 'nvidia-smi topo -m' show and why is it important for multi-GPU troubleshooting? | Shows GPU-GPU and GPU-NIC topology (NVLink, PCIe, SYS paths). NV# = NVLink hops, SYS = across NUMA/socket. Exam tip: If slow multi-GPU perf, check if GPUs have NVLink (NV1-NV4) or only PCIe/SYS. For NCCL, also shows which GPUs are near which NICs (NODE vs SYS). |
