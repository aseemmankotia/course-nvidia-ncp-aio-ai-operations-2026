## Chapter 6: Multi-Tenant Workload Deployment: Inference and Training — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | NVIDIA NIM deployment on Kubernetes: required resource request field for GPU allocation? | nvidia.com/gpu: <count> in the container resources.requests section. Also set resources.limits to same value. Exam tip: Without this field, pod won't schedule on GPU nodes. NGC NIM containers require GPU, will fail on CPU-only nodes. |
| 2 | Triton Inference Server: config.pbtxt settings for dynamic batching? | dynamic_batching { max_queue_delay_microseconds: <μs> preferred_batch_size: [<sizes>] max_batch_size: <max> }. Exam tip: max_queue_delay controls latency vs throughput tradeoff. Higher = better throughput, worse latency. |
| 3 | Slurm sbatch flags for 4-node, 8-GPU-per-node distributed training? | --nodes=4 --gres=gpu:8 --ntasks-per-node=8. Exam tip: ntasks-per-node MUST match GPU count for PyTorch DDP. --ntasks without -per-node creates tasks across all nodes (wrong). gres is per-node. |
| 4 | NCCL environment variable to specify InfiniBand device when auto-detect fails? | NCCL_IB_HCA=<device_name> (e.g., mlx5_0, mlx5_1). Also set NCCL_IB_DISABLE=0. Exam tip: mlx5 = Mellanox/NVIDIA. Error 'No device found' means need explicit HCA. Use ibstat or ibv_devices to find name. |
| 5 | Run:ai submit command: flags for 4 workers × 8 GPUs with gang scheduling? | runai submit <name> --replicas 4 --gpu 8 --gang-scheduling --distributed-launch torch. Exam tip: --workers is WRONG (not valid flag). --gpu applies per replica. Gang scheduling = all pods start together or none. |
| 6 | Triton model repository structure: where to place model files and config? | model_repository/<model_name>/<version>/model.<format> and model_repository/<model_name>/config.pbtxt. Exam tip: version is numerical folder (1/, 2/). config.pbtxt at model_name level, not version level. Triton auto-loads on startup. |
| 7 | NCCL for Ethernet cluster: which env var to select high-speed interface? | NCCL_SOCKET_IFNAME=<interface> (e.g., eth1, enp94s0f0). Exam tip: Default may pick 1Gbps mgmt network. 'Using network Socket' in debug = check interface. Use ifconfig/ip a to find 100Gbps interface name. |
| 8 | Slurm srun vs sbatch: which for interactive multi-GPU job testing? | srun --nodes=1 --gres=gpu:8 --pty bash (interactive). sbatch submits batch script to queue. Exam tip: srun blocks terminal, immediate execution. sbatch returns job ID, runs async. Both use same flags (--nodes, --gres). |
| 9 | Triton dynamic batching: max_queue_delay_microseconds impact on latency? | Adds up to <μs> delay to batch requests. 0 = no batching (low latency, low throughput). 50000 (50ms) = high batching (high throughput, +50ms latency). Exam tip: p95 latency sensitive = low delay. Throughput critical = high delay. |
| 10 | Run:ai gang scheduling: what happens if resources unavailable for all replicas? | Job stays pending, NO pods start (all-or-nothing). Without gang scheduling, partial pods start → distributed training hangs waiting for peers. Exam tip: Gang scheduling essential for multi-pod training. Prevents partial deployment failures. |
| 11 | NCCL_DEBUG levels and when to use each? | INFO = verbose (init issues, device detection), WARN = default (errors/warnings), VERSION = minimal. Exam tip: NCCL_DEBUG=INFO shows 'Using network <type>' to debug slow communication. Set to WARN in production (less overhead). |
| 12 | Kubernetes GPU resource: nvidia.com/gpu as request vs limit difference? | Must set BOTH to same value. GPUs are not overcommitable. request = scheduling, limit = runtime. Exam tip: Mismatch causes scheduling errors. Extended resources (GPU) don't support fractional/overcommit like CPU/memory. |
