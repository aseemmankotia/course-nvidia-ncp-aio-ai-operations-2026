## Chapter 9: Exam Simulation and Test-Taking Strategy — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | NCP-AIO exam: Recommended time allocation for 30 MCQs? | 40 minutes (1.3 min per question average). Leaves 80 minutes for 3 hands-on labs. Exam tip: Finish MCQs early if possible—extra time rolls to labs, but lab time doesn't roll back to MCQs. |
| 2 | NCP-AIO exam: Recommended time per hands-on lab? | 25-30 minutes per lab including verification and buffer. Total 80 minutes for 3 labs from 120-minute exam. Exam tip: If a lab has 4 tasks and you're at 20 min with 2 tasks left, prioritize completing 1 task fully over rushing both. |
| 3 | Lab strategy: You're stuck on task 2 of 4 in a lab with 10 minutes left. What should you do? | Move to task 3 and 4—attempt the easiest remaining task. Labs award partial credit per task. A completed task 4 is better than incomplete task 2. Return to task 2 only if time permits. Exam tip: Stuck = move on, return later. |
| 4 | MCQ strategy: 'BEST' vs 'CORRECT' in exam questions? | 'BEST' = multiple options may work, choose the most complete/efficient/recommended. 'CORRECT' = only one option is technically accurate. Exam tip: BEST questions often test BCM vs Run:ai, or Slurm vs K8s—choose the most comprehensive NVIDIA solution (usually BCM for enterprise). |
| 5 | Lab documentation available during NCP-AIO exam? | Base Command Manager official docs, Slurm man pages (man sinfo, man srun, etc.), kubectl --help, kubectl explain. NO internet access. Exam tip: 'kubectl explain pod.spec.containers.resources' shows GPU resource syntax instantly. |
| 6 | Command to verify Slurm partition with node count and GPU resources? | sinfo -o '%P %D %G' (shows Partition name, node count (D), GRES/GPU count (G)). Exam tip: Faster than 'scontrol show partition' for quick verification. Memorize -o format string. |
| 7 | Kubernetes pod pending with GPU request—fastest troubleshooting command? | kubectl describe pod <name> (check Events section for scheduling failures like 'Insufficient nvidia.com/gpu'). Then verify node GPU capacity: kubectl get nodes -o json \| grep nvidia.com/gpu. Exam tip: 'describe' first, always. 30-second diagnosis. |
| 8 | Common MCQ trap: BCM vs Mission Control for cluster management? | BCM = job scheduling + resource quotas + user access control (cluster workload management). Mission Control = fleet monitoring + ops for multiple DGX systems (fleet management, not workloads). Exam tip: Cluster workload question = BCM. Fleet ops/monitoring question = Mission Control. |
| 9 | Common MCQ trap: MIG vs fractional GPU in multi-tenant scenarios? | MIG (Multi-Instance GPU) = hardware partitioning of A100/H100 into isolated instances with memory/compute boundaries. Fractional GPU = time-slicing, processes share GPU memory. Exam tip: Isolation/security requirement = MIG. Simple sharing = fractional. MIG = A100/H100 only. |
| 10 | Common MCQ trap: Fabric Manager vs NVSwitch NVOS? | Fabric Manager = userspace daemon managing NVLink topology and GPU-to-GPU communication (the 'responsible component'). NVSwitch NVOS = OS running on NVSwitch ASICs (low-level packet routing). Exam tip: 'Which component is responsible' = Fabric Manager. 'What runs on the switch' = NVOS. |
| 11 | Run:ai quota calculation trap in exam questions? | Run:ai enforces quotas at project/department level using Kubernetes resource quotas. Trap: confusing node-level GPU count vs project-level quota limits. Exam tip: If question asks 'user can request X GPUs but project quota is Y,' answer is constrained by Y (quota), not node capacity. |
| 12 | Lab verification checklist: What to confirm before submitting? | 1) Run verification command (sinfo, kubectl get pods, nvidia-smi). 2) Confirm output matches task requirements exactly (node count, GPU count, pod status=Running). 3) If multi-step task, verify each step's output. Exam tip: Spend 30 sec verifying vs 5 min debugging later. Output match = submit. |
