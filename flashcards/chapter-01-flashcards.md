## Chapter 1: Base Command Manager: Installation and Cluster Initialization — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | BCM architecture: What are the three core components of a Base Command Manager cluster? | 1) Head node (runs BCM services, database, scheduler), 2) Management network (control plane for node communication), 3) Compute nodes (GPU/CPU workers). Exam tip: Head node is single point of failure unless HA configured; management network must be isolated from job data traffic. |
| 2 | cmsh command: Add a new compute node named 'gpu001' with IP 10.0.1.101 to the cluster | device add gpu001 ip=10.0.1.101 Exam tip: Must specify IP during add; use 'device clone' to copy settings from existing nodes; verify with 'device list' before syncing. |
| 3 | BCM roles: What are the three standard user roles and their key permissions? | 1) admin: full cluster management, node provisioning, user management; 2) operator: view/manage all jobs, node status monitoring, limited config; 3) user: submit own jobs, view own job status, access compute resources. Exam tip: User role CANNOT see other users' jobs or modify cluster config. |
| 4 | Base View monitoring: What four GPU metrics does Base View display by default? | 1) GPU utilization (%), 2) Power consumption (watts), 3) Temperature (°C), 4) Memory utilization (%). Exam tip: Requires NVIDIA DCGM running on compute nodes; metrics update every 30-60 seconds; 'N/A' means DCGM not reporting. |
| 5 | cmsh command: Create a node category named 'h100-partition' and assign nodes gpu001-gpu032 to it | category add h100-partition category use h100-partition device assign gpu[001-032] Exam tip: Use bracket notation [001-032] for ranges; verify with 'category show h100-partition'; categories enable scheduler partitioning. |
| 6 | BCM installation: What database does BCM use and what must exist before BCM initialization? | PostgreSQL database. Must be installed, running, and accessible before running BCM installer. Exam tip: 'database connection timeout' during init = PostgreSQL not running; BCM creates schemas automatically but needs working PostgreSQL service. |
| 7 | Image sync: What's the difference between 'device sync' and 'device update' in cmsh? | 'device sync': pushes software image (OS, apps) to nodes. 'device update': applies firmware/BIOS updates. Exam tip: sync can run on live nodes; update usually requires reboot; both respect job status unless --force used. |
| 8 | BCM hardware requirement: What is the minimum requirement for head node installation? | NVIDIA-certified server hardware listed in BCM compatibility matrix. Exam tip: Non-certified hardware not supported; head node needs redundant PSU and RAID for production; compute nodes can be non-certified if drivers compatible. |
| 9 | Node status in Base View: What does 'unknown' status indicate vs 'not ready' status? | 'unknown': no heartbeat from node, communication lost. 'not ready': node responsive but not accepting jobs (maintenance mode, initializing, or failed health checks). Exam tip: unknown = network/power issue; not ready = intentional state or node problem. |
| 10 | cmsh command: Display detailed status of all devices including last heartbeat and connection state | device list -s (or device list --status) Exam tip: Shows communication failures, last contact time, OS version; use for diagnosing 'unknown' nodes; add 'device list -s \| grep unknown' to filter. |
| 11 | Software image management: What components can be bundled in a BCM software image? | OS distribution (Ubuntu/RHEL/Rocky), NVIDIA drivers, CUDA toolkit, containerization runtime (Docker/containerd), custom applications, firmware version (optional). Exam tip: One image can be assigned to multiple node categories; changes require sync to apply. |
| 12 | Access control: What happens if a user account is created without a role assignment in BCM? | User can authenticate but has no permissions to submit jobs, access compute nodes, or use BCM features. Exam tip: Always assign role during account creation; default role is NOT automatically assigned; POSIX permissions alone insufficient for BCM operations. |
